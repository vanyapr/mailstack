# MailStack

[English version](README.md)

Подробности: [архитектура](docs/ARCHITECTURE.md), [развёртывание](docs/DEPLOYMENT.md), [локальная разработка и тесты](docs/DEVELOPMENT.md), [участие в проекте](CONTRIBUTING.md), [безопасность](SECURITY.md).

## 0. Какую проблему решаем

Собственная почта обычно требует одновременно поддерживать почтовый сервер,
веб-интерфейс, учётные записи, доставку, резервные копии и обновления. MailStack
собирает эти части в один продукт: почтовый сервер остаётся источником данных, а
пользователь и администратор получают отдельные понятные веб-интерфейсы.

## 1. Что за продукт

MailStack — самостоятельно разворачиваемый почтовый продукт на базе
[Mox](https://www.xmox.nl/). Его веб-приложение написано на Next.js и работает как
серверный BFF: браузер не обращается к внутренним API Mox напрямую. Mox хранит
письма, папки, учётные записи и отвечает за доставку; MailStack предоставляет
интерфейс почты и управления.

В поставку также входят контроллер установки и обслуживания, Docker-образы и
Ansible-роли. Они создают только ресурсы MailStack и не должны самостоятельно
изменять существующие сайты или чужую почтовую установку.

## 2. Что делает

- Даёт почтовый интерфейс: папки, поиск, чтение HTML-писем в изолированной
  области, вложения, черновики, создание и отправку писем, ответы и пересылку.
- Хранит почту в Mox, а не в отдельной базе MailStack; пользовательские сессии и
  права доступа обрабатываются серверной частью приложения.
- Даёт администратору обзор сервера, управление доменами, ящиками и алиасами,
  просмотр очереди доставки, диагностику и сведения о резервных копиях.
- Разворачивается контроллером с проверяемыми Docker-образами и Ansible. Перед
  активацией он проверяет принадлежащую MailStack конфигурацию Nginx и оставляет
  чужие сайты нетронутыми.
- Поддерживает проверяемое резервирование и восстановление в отдельный
  неактивный каталог; откат приложения возвращает предыдущий проверенный образ,
  не объявляя почтовые данные автоматически обратимыми.

## 3. Что не делает

- Это не почтовый SaaS и не поставщик домена, DNS, TLS-сертификатов или внешнего
  резервного хранилища: владелец выбирает и контролирует эти ресурсы сам.
- MailStack не заменяет Mox и не создаёт вторую базу писем, папок или аккаунтов.
- Он не обнаруживает произвольный сервер и не выполняет unattended-установку:
  цель, проверенный SSH host key, домен, DNS/TLS-план и внешнее резервирование
  должны быть определены до запуска.
- Он не захватывает существующий Mox автоматически. Режим подключения к нему
  возможен только после проверки совместимости и плана отката.
- Успешная локальная сборка или CI сами по себе не подтверждают публичную
  доставку писем, DNS, TLS и восстановление из резервной копии.

## 4. Как ставить

Для локального знакомства нужны Python 3.12+, работающий Docker Engine/Desktop
с Compose v2 и BuildKit и свободный локальный порт 3100:

```sh
git clone https://github.com/vanyapr/mailstack.git
cd mailstack
./mailstack dev
```

Эта команда поднимает изолированный стенд с синтетическими данными. Он не
требует публичного домена и не отправляет почту внешним получателям.

Установка на сервер выполняется только после подготовки утверждённой Linux-цели,
проверенного SSH host key, домена, DNS- и TLS-плана и внешнего резервного
хранилища. Защищённый конфигурационный файл и проверяемые архивы образов хранятся
вне Git:

```sh
./mailstack install --config /path/to/protected-install.json
```

Контроллер сверяет права конфигурационного файла, host key, неизменяемые образы и
маркеры владения ресурсами. Он не должен использоваться для автоматического
изменения неизвестных серверов. Полные требования к установке, резервированию и
откату описаны в [руководстве по развёртыванию](docs/DEPLOYMENT.md).

Исходный код MailStack распространяется по [MIT](LICENSE); лицензии Mox и библиотек сохраняются отдельно в исходниках и [уведомлениях о компонентах](apps/web/public/THIRD-PARTY-NOTICES.txt). Не добавляйте в публичный репозиторий письма, адреса реальных ящиков, ключи и конфигурацию сервера.

## 5. Где вход, где интерфейс администратора

Адреса зависят от hostname, выбранного при установке:

- `https://<hostname>/` перенаправляет в почту.
- `https://<hostname>/mail` — вход пользователя. Используйте адрес почтового
  ящика и его пароль.
- `https://<hostname>/admin` — административная панель. Для неё нужен отдельный
  пароль администратора Mox, а не пароль обычного почтового ящика.

Администратор может открывать пользовательскую почту из панели, но пользователь
без административной сессии не получает доступа к разделам управления.
